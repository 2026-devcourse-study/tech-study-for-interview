### 1️⃣ 핵심 개념 한 줄
> DDD : DDD는 복잡한 비즈니스 도메인을 효과적으로 모델링하기 위한 설계 방법론이다. <br>
> 전략적 DDD: 비즈니스 전체의 방향과 구조를 잡는 것 (무엇을 만들고, 어떻게 나눌 것인가?)
> 전술적 설계 DDD: 결정된 구조 내부의 구현 상세를 다루는 것 (어떤 코드로 구현할 것인가?)

---

### 2️⃣ 동작 원리 요약

- **왜 필요한가?**
  - 
  ```
    과거 엔터프라이즈 시스템은 아래와 같은 DB를 중심으로 하는 구조가 일반적이었으나, 이는 비즈니스가 복잡해질수록 코드 영역에서
  유지보수가 힘들어지고, 도메인 모델링이 힘들어지는 문제점이 있었다. DDD는 이러한 설계의 문제점을 해결할 때에 필요하다.
  
  비즈니스 규칙이 복잡할 때, 정책이 많고 자주 바뀔 때 등에 필요하다.
  금융 시스템, 정산 시스템, 커머스 주문/결제, 멤버십/포인트 시스템 등..
  ```
  
- **어떻게 동작하는가?**
  - 
    ```
    DDD에서는 도메인을 이해하는 것이 먼저다. DDD는 Domain 모델을 중심으로 동작한다.
    요청이 들어오면 Application Layer가 트랜잭션을 시작하고
    Domain에 속한 Entity 객체의 메서드를 호출하여 비즈니스 규칙을 실행한다.
    Domain은 스스로 불변 조건을 보장하고, Infrastructure에서는 기술 구현 및 영속성을 담당한다.
    ```

### 5️⃣ 자주 나오는 면접 질문 (선택)

- Q.DDD는 어떤 문제를 해결하려고 나온 방법론인가요?
    - A : 
        ```
        DDD는 복잡한 비즈니스 도메인을 효과적으로 모델링하기 위해 등장한 설계 방법론입니다.
        기존의 DB 중심 설계는 로직이 서비스 계층에 집중되면서 유지보수가 어려워졌고,
        DDD는 도메인 객체가 스스로 책임을 가지도록 하여 복잡한 비즈니스 규칙을 코드에 자연스럽게
        반영하려는 목적을 가지고 있습니다.
        ```
- Q.DDD에서 엔티티(Entity)와 밸류 객체(Value Object)의 가장 큰 차이점은 무엇인가요?
    - A : 
        ```
        가장 큰 차이는 식별자(ID)의 유무이다. Entity는 식별자(ID)를 기준으로 동일성을 판단하고,
        Value Object는 값 자체로 동일성을 판단하기 때문이다.
        따라서 VO는 값이 바뀌면 새로운 객체로 교체해야 하며, VO는 불변 객체로 설계하는 것이 일반적이다.
        ```
    
- Q. 왜 VO를 불변으로 만들어야 하나요?
    - A : 
        ```
        VO는 여러 곳에서 참조될 수 있는데, 한 곳에서 값을 변경했을 때 의도치 않게 다른 곳의 데이터까지 변하는 '부수 효과(Side Effect)'를 방지하여 코드의 예측 가능성을 높이기 위해서입니다.
        ```
    
- Q. 애그리거트(Aggregate)란 무엇이며, 왜 이를 설정하는 것이 중요한가요?
    - A : 
        ```
        애그리거트는 관련 객체들을 하나의 군집으로 묶어 데이터 변경의 일관성을 유지하는 단위입니다. 애그리거트 없이 수많은 엔티티가 서로 복잡하게 참조하면, 데이터 수정 시 어디까지 변경해야 할지 알기 어렵고 트랜잭션 범위가 모호해집니다. 
        애그리거트를 통해 도메인의 복잡도를 낮추고 캡슐화를 강화할 수 있습니다.
        ```
    
- Q. Aggregate Root는 왜 필요한가요? 모든 엔티티를 직접 수정하면 안 되나요? 애그리거트 루트(Root)를 통해서만 내부 객체에 접근해야 하는 이유는 무엇인가요?
    - A : 
        ```
        애그리거트 내부의 데이터 일관성과 불변 조건(Invariant)을 강제하기 위해서입니다. 외부에서 애그리거트 내부 객체를 직접 수정하게 되면, 전체적인 비즈니스 규칙이 깨질 수 있습니다.
        반드시 외부 루트를 통해서만 내부 객체를 변경할 수 있도록 하여 무결성을 책임지게 합니다.
        ```
