### 1️⃣ 핵심 개념 한 줄

> **Transaction**은 여러 작업을 하나의 논리적인 작업 단위로 묶어 모두 성공하거나 모두 실패하는 것을 보장하는 개념입니다.<br>
>
> **AOP**는 여러 비즈니스 로직에서 공통적으로 처리되는 부가기능인 공통 관심사를
> 비즈니스 로직과 분리해 메서드 실행 전, 후에 공통로직을 삽입하는 기법입니다. <br>
---

### 2️⃣ 동작 원리 요약

- **왜 필요한가?**
    - 작업 도중 장애가 발생하더라도 데이터의 일관성과 무결성을 유지하기 위해 `Transaction`이 필요합니다.<br>
      이는 부분 성공으로 인한 데이터 불일치를 방지합니다.<br>
    - `AOP`는 트랜잭션, 로깅 등과 같은 공통 관심사를 분리해 코드 중복을 제거하고, 유지보수성을 향상시킵니다.
- **어떻게 동작하는가?**
    - @Transactional은 AOP를 기반으로 동작합니다.<br>
        - **동작 흐름**<br>
            1. @Transactional을 클래스나 메서드 레벨에 선언
            2. 스프링이 빈을 생성할 때 대상 객체(Target)를 프록시로 감싸 컨테이너에 등록
            3. 메서드 호출 시 프록시 객체가 메서드 호출을 가로채 공통 관심사를 실행 (트랜잭션 시작)
            4. 프록시 객체 실행 후, target 메서드를 호출
            5. 메서드 정상 종료 시 commit. 예외 발생해 프록시 밖으로 전파되면 rollback

### 5️⃣ 자주 나오는 면접 질문 (선택)

- **Q.ACID가 무엇인가요?**
    - Atomicity(원자성): 모두 성공하거나 모두 실패
    - Consistency(일관성): 트랜잭션 전후 데이터는 항상 규칙, 제약조건 만족
    - Isolation(격리성): 동시에 실행되어도 독립적으로 실행되는 것처럼 보임
    - Durability(영속성): commit된 데이터는 장애 발생 시에도 영구 저장
- **Q. @Transactional이 적용되지 않은 경우는 어떤 경우인가요?**
    - private 메서드이거나, 같은 클래스 내부에서 메서드를 호출(self-invocation)하거나,
      final 클래스나 메서드를 호출하는 경우에는 @Transactional이 적용되지 않습니다.

### 6️⃣ 꼬리 질문 & 대응 포인트 (선택)

- 꼬리 질문: **프록시 객체란 무엇인가요?**
- 대응 논리: 실제 객체를 대신해 호출을 먼저 받아 부가 기능을 수행한 후 실제 객체를 호출하는 대리 객체입니다.
- 꼬리 질문: **왜 private 메서드는 안 되나요?**
- 대응 논리: 프록시는 외부 호출을 가로채는 방식이라 private 메서드는 대상이 되지 않습니다.
