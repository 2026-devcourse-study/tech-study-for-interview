### 2️⃣ 동작 원리 요약

- **왜 필요한가?**
  - 서로 다른 트랜잭션이 하나의 데이터에 동시에 동작했을때 결과가 예측 불가능한 상황이 있다  
  - 은행계좌 잔액이 100원일때 서로 다른 트랜잭션 A, B 가 동시에 조회후 변경을 가한다면  
  - A 100 조회 -> 50 출금, B 100 조회 -> 70 출금   
  - 잔액은 50 -> 30 이거나 30 -> 50 이 될 수 있음  
  - 이러한 상황을 막기 위해서 나온 기술이다
- **어떻게 동작하는가?**
  - 비관락: 어차피 같이 건드릴거야
    1. 트랜잭션 시작
    2. 데이터 조회와 동시에 락 획득
    3. 다른 트랜잭션은 접근 불가
    4. 작업 완료 후 커밋
    5. 락 해제
  - 낙관락: 동시에 건드릴일이 없을거 같은데?
    1. 데이터 조회
    2. 작업 수행
    3. 업데이트 시점에 버전 비교
    4. 버전이 다르면 -> 실패
    ```
    UPDATE account
    SET balance = 50, version = version + 1
    WHERE id = 1 AND version = 3;
    ```
    영향받은 row = 0 -> 충돌발생
