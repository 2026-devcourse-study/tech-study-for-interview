### 📍 Topic A – 논블로킹/비동기

---

### 1️⃣ 핵심 개념 한 줄
> 동기란 요청한 작업의 결과가 나올 때까지 기다리거나, 결과가 나오면 즉시 처리하는 방식이고, 비동기는 작업을 요청한뒤, 결과를 나중에 받는 방식이다. 호출하는 함수는 호출되는 함수에게 콜백(Callback) 함수를 건네주고, 자신의 할 일을 계속한다. <br>
> 블로킹: 호출된 함수가 작업을 완료할 때까지 제어권을 계속 가지고 있는 상태이다. 즉, 요청한 작업이 끝날 때까지 현재 스레드는 멈추게 된다.  </br>
> 논블로킹: 호출된 함수가 작업을 마치지 않았더라도 제어권을 즉히 호출한 함수에게 돌려주는 상태이다. 작업이 즉시 끝나지 않더라도, 스레드를 멈추지 않는다. 그렇기에 다른 작업들을 계속 진행할 수 있다.  <br>
> Thread 기반 모델: Thread 기반 모델이란, 작업을 처리하는 기본 단위를 스레드(Thread)로 사용하는 실행 모델으로, 요청마다 스레드(Thread)를 할당해서 동시에 여러 요청을 처리하는 모델이다. </br>
> 핵심 : Thread 기반 모델은 블로킹/논블로킹 방식으로 스레드를 어떻게 쓰느냐를 결정하고, 그 위에서 동기 또는 비동기 방식으로 결과를 처리한다고 볼 수 있다.

---

### 2️⃣ 동작 원리 요약

- **왜 필요한가?**
  - 논블로킹은 스레드를 효율적으로 사용하기 위한 전략이다. I/O 대기가 많고 동시 요청이 많은 경우에는 효과적이지만,
CPU 연산 위주이거나 복잡도가 중요한 경우에는 오히려 불리할 수 있다.
  - 논블로킹 + 비동기는 빠르게 만들기 위해서가 아니라, '많은 요청을 버티기 위해' 필요하다. 
  
- **어떻게 동작하는가?**
  - 블로킹 I/O + Thread 기반 모델
    - 요청이 들어오면 스레드 1개가 요청 1개에 할당됨
    - 요청 처리 완료까지 해당 스레드 대기, 대기 시간 동안 아무 일도 못 함
    - 요청 많아질수록 스레드 고갈
    - 전통적인 Spring MVC + JDBC 구조 <br>
  - 논블로킹 I/O + Thread 기반 모델
    - 스레드가 멈추지 않음
    - 소수 스레드로 다수 작업 처리 가능
    - CPU 활용률 높아짐
    - Context Switching 감소
    - Netty, WebFlux 구조

### 5️⃣ 자주 나오는 면접 질문 (선택)

- Q.블로킹(Blocking)과 논블로킹(Non-blocking)의 차이는 무엇인가요?
    - A: 
    ```
    블로킹과 논블로킹은 **함수를 호출했을 때 호출한 스레드가 멈추는지, 제어권을 누가 가지는지에** 대한 개념입니다.

블로킹 방식은 작업이 끝날 때까지 스레드가 대기 상태에 들어가고, 호출된 함수에게 제어권을 넘겨주게 됩니다. 즉, 호출된 함수가 작업을 완료할 때까지 **제어권을 계속 가지고 있게 됩니다.**

논블로킹 방식은 작업 완료 여부와 상관없이 즉시 제어권을 반환받아 스레드가 계속 실행됩니다.

즉, 블로킹/논블로킹은 **스레드 제어 관점**의 개념입니다.
```
- Q. 동기/비동기와 블로킹/논블로킹은 어떻게 다른가요?
    - A:
    ```
    동기/비동기는 과를 언제 어떻게 받는지에 대한 개념이고,

블로킹/논블로킹은 **스레드가 멈추는지 여부**에 대한 개념입니다.

서로 다른 축의 개념이기 때문에 조합이 가능합니다
```

- Q. Thread 기반 모델에서 블로킹 방식의 문제점은 무엇인가요?
```
블로킹 방식에서는 요청 하나당 스레드를 점유하고,
I/O 대기 동안에도 스레드가 아무 작업을 하지 못합니다.
동시 요청이 많아지면 스레드 수 증가, 컨텍스트 스위칭 비용 증가로 인해
성능 저하와 서버 자원 고갈 문제가 발생할 수 있습니다.
```

### 6️⃣ 꼬리 질문 & 대응 포인트 (선택)

- 꼬리 질문: 실무에서 논블로킹 도입 기준은?
- 대응 논리: I/O 병목 + 동시성 요구 + 팀 숙련도
</br>
- 꼬리 질문: 블로킹 논/블로킹에서 말하는 제어권이 어떤 제어권인지?
- 대응 논리: 여기서 말하는 제어권은 '현재 실행 중인 스레드의 실행 흐름을 계속 진행할 수 있는 권리'를 의미한다.
```
블로킹/논블로킹에서 말하는 제어권은
함수 호출 이후 호출한 스레드가 계속 실행 흐름을 이어갈 수 있는지에 대한 개념입니다.
블로킹은 스레드가 대기 상태로 전환되어 제어권을 OS에 넘기는 것이고,
논블로킹은 즉시 반환되어 스레드가 실행 흐름을 유지하는 방식입니다.
```
