### 📍 Topic A - 객체지향 설계 / SOLID / Tomcat

---

### 1️⃣ 핵심 개념 한 줄
> SOLID는 객체지향 4대 특성을 기반으로, 변화에 유연하고 유지보수가 쉬운 구조를 만들기 위한 5가지 설계 원칙입니다.
> Apache Tomcat 은 자바 서블릿과 JSP를 실행하는 서블릿 컨테이너로, HTTP 요청을 받아 서블릿을 통해 처리하고 응답을 반환하는 웹 애플리케이션 실행 환경입니다.
---

### 2️⃣ 동작 원리 요약

- **왜 필요한가?**
  - 요구사항은 계속 변경됨
  - 수정 범위를 최소화해야 함
  - 결합도를 낮춰야 테스트 용이

좋은 설계란:
> 변경이 발생했을 때 영향을 받는 코드가 적은 구조
- **어떻게 동작하는가?**
  - 추상화 기반 설계
  - 인터페이스 활용
  - 다형성 이용
  - 상속보다는 합성

톰캣 요청 흐름:

- 클라이언트가 HTTP 요청 전송
- Tomcat의 Connector가 요청 수신
- URL 매핑 후 서블릿 결정\
- service() 호출
- 응답 반환

스프링 MVC 구조에서는:
- 모든 요청 → DispatcherServlet
- HandlerMapping → 컨트롤러 탐색
- HandlerAdapter → 메서드 실행

ViewResolver → 응답 생성

### 3️⃣ SOLID 5원칙 정리
🔹 SRP

하나의 클래스는 하나의 책임만 가져야 한다.

🔹 OCP

확장에는 열려 있고 수정에는 닫혀 있어야 한다.
- 전략 패턴
- 인터페이스 기반 설계

🔹 LSP

자식 클래스는 부모를 대체해도 정상 동작해야 한다.

🔹 ISP

클라이언트가 사용하지 않는 인터페이스에 의존하게 하지 말라.

🔹 DIP

구현이 아닌 추상화에 의존하라.
